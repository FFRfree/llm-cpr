# 长会话不做额度迁移，保上游 prompt cache

错误迁移会把会话换到另一个 backend，上游 prompt cache 全部作废；对请求轮数 ≥ `routing.long_session_min_requests`（默认 10，0 关闭）的会话，网关不迁移、原样透传错误（含 retry-after），由客户端稍后重试原 backend。用户拍板（2026-11-17）：**缓存前缀连续性 > 池内调度**——为省一份订阅的额度而烧掉整个会话的缓存，整体上是亏的。

没有上下文的人会以为这是 bug（「网关怎么见死不救」），所以记录在案：这是刻意的，且不提供 per-会话开关。
