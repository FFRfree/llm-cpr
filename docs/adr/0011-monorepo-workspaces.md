# monorepo：pnpm workspace 管四个内部包，一个发布入口，发布物装配而非发链接

仓用 pnpm workspace 管理（`pnpm-workspace.yaml`，`packageManager` 钉版本），四个包：`packages/core`（引擎：路由 + 管理面 + 看板分发，private；源码目录 src/，发布物里经 assemble 映射成 core/——发布布局自 v0.2.0 冻结；将来上编译即 src→dist，映射点在 assemble）、`packages/dashboard`（看板页面源码唯一正本，build 产物落 `packages/core/static/`，private）、`packages/e2e`（e2e 套件：假上游 + 独立实例 + pi harness，快车道 `run-scenarios.ts` + 慢车道 rootless podman，private）、`packages/cli`（`@ffrfree/llm-cpr`，**唯一发布到 npm 的包**，bin/引导器/vendor/模板）。发布时 `prepack` 跑 `scripts/assemble.ts` 把 core+static 拷进 cli 包再 pack——发布物内布局与 v0.2.0 以来完全一致（`core/ + static/ + scripts/` 同根），bootstrap/安装/升级机器零改动。取舍：换来页面源码、e2e 与引擎解耦（dashboard 可换 React/Vite 而不动 core 与 cli）和清晰的发布入口（core/dashboard/e2e 不单独占版本号，永远随 cli 同步发版）；代价是跨包引用不能走 npm 包名——Node 拒跑 node_modules 路径下的 `.ts`（ERR_UNSUPPORTED_NODE_MODULES_TYPE_STRIPPING，ADR-0008 工单 12），workspace 软链恰是 node_modules 路径，所以包间只有构建期的产物装配关系，没有运行期的包依赖关系，仓库根保持零构建。clone 判定与包根推算在 `packages/cli/scripts/cpr.ts` 的 `pkgRoot/engineRoot/gitRoot` 三件套里归一；e2e 与慢车道脚本自动探测 pack 源 = `packages/cli`。
