# 配置即代码：订阅声明与路由策略收进 policy class

旧形态是订阅声明放 config.json 由运行时加载、支持热重载；2026-11-18 拍板改为「声明 + decide 全在 `core/policy/mine.ts`，随 release 发布」：改配置 = 改代码 = 走 typecheck + 测试 + 假上游冒烟 + release 切换。理由：声明从此受类型与测试保护，坏声明拒绝启动；而声明变更本来就该按代码变更的纪律走，热重载省下的几分钟不值得引入「运行时加载层的正确性」这个新问题。

## Considered Options

- 保留 config.json：轻，但声明无类型保护、校验全靠运行时，且加载层自带一类 bug（路径、mtime、软链）。
- 外置 .ts 文件启动时加载：保住「policy 是代码」的手感，但多一套文件发现与边界约定，收益对单用户场景不成比例。

## Consequences

改一次声明要发一次 release（重、但罕见且有冒烟兜底）；将来开源若需要「用户声明放仓外」，那是启动入口的问题，不是契约问题——届时单独拍板。
