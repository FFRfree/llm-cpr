# 02: 路由身份与会话钉死

**What to build:** 路由身份三级兜底（统一会话头 → 对话指纹：system+首条 user 内容哈希，仅 chat/completions → 客户端地址）与身份→订阅映射存储（node:sqlite）。新身份先按"第一个健康后端"选定（评分在 03 号票），映射落库后该身份永久钉死该订阅，后续请求不再改选。无会话头的客户端（hindsight 式后台调用）走指纹身份也能被稳定钉死。

**Blocked by:** 01（需要配置与转发骨架）

**Status:** ready-for-agent

- [ ] 单测：身份解析三级兜底（带头/无头/极端输入）、指纹稳定性（同对话同指纹、首条消息变更即换）
- [ ] e2e（两个假后端）：同会话头多次请求全部落同一后端；无会话头的同对话（同前缀）也钉死；不同对话可落不同后端
- [ ] 映射持久化：进程重启后同一身份仍钉原订阅（沿用 ocg-proxy 的表结构先例）
- [ ] `node --test` 全绿；中文 commit；工作树干净
